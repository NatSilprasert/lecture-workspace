# 3. File-System Interface

## ภาพรวม

บทนี้อธิบายมุมมองที่ผู้ใช้และโปรแกรมมีต่อ file system ได้แก่ ความหมายของ file, file attributes, วิธีเข้าถึงข้อมูล, directory structure, การ mount, การแชร์ไฟล์ และการป้องกันสิทธิ์

## 1) File Concept

- file คือหน่วยเก็บข้อมูลเชิงตรรกะ (`logical storage unit`)
- มองเป็นลำดับข้อมูลต่อเนื่อง
- เนื้อหาและชนิดขึ้นกับผู้สร้าง เช่น text, source, executable, binary

แนวคิดสำคัญ:

- file เป็น `abstract data type`
- ผู้ใช้สนใจชื่อและการใช้งาน มากกว่าตำแหน่งจริงบน disk

## 2) File Attributes

คุณสมบัติที่ file system มักเก็บ เช่น

- name
- identifier
- type
- location
- size
- protection
- time / date / user identification

ข้อมูลเหล่านี้มักถูกเก็บใน `directory structure`

## 3) File Operations พื้นฐาน

การทำงานที่พบบ่อย:

- create
- open
- read
- write
- seek / reposition
- close
- delete
- truncate

จุดสำคัญ:

- `open()`search the directory structure on disk for entry Fi , and move the content of entry to memory
- `close()` move the content of entry Fi in memory to directory structure on disk

## 4) File Structure และ Access Methods

โครงสร้างข้อมูลใน file อาจเป็น:

- stream ของ bytes
- records แบบง่าย
- structures ที่ซับซ้อนขึ้น

วิธีเข้าถึงหลัก:

- `Sequential access`
อ่าน/เขียนตามลำดับ เหมาะกับงาน stream
- `Direct access`
เข้าถึง block หรือ record ตามตำแหน่งได้ทันที
- วิธีอื่น เช่น indexed methods

ขยายความ:

- `Sequential access`
เหมือนอ่านหนังสือจากหน้า 1 ไปหน้า 2 ไปเรื่อย ๆ ถ้าจะไปข้อมูลถัดไปก็เลื่อนต่อจากตำแหน่งเดิม เหมาะกับการอ่านไฟล์เพลง, วิดีโอ, log, หรือไฟล์ข้อความยาว ๆ
- `Direct access`
เหมือนเปิดหนังสือไปหน้าที่ 80 ได้เลยโดยไม่ต้องไล่ทีละหน้า เหมาะกับงานที่ต้องกระโดดไปอ่าน record หรือ block บางตำแหน่ง เช่น database หรือการแก้ข้อมูลบางส่วนของไฟล์

ตัวอย่าง:

- ถ้าอ่านไฟล์ subtitle หรือ log จากบนลงล่างเรื่อย ๆ นี่คือ `sequential access`
- ถ้าต้องการแก้ record ที่ 500 ของไฟล์ทันที นี่คือ `direct access`

`Other access methods`:

- มักสร้างเพิ่มบนพื้นฐานของวิธีหลัก เช่น `sequential` หรือ `direct access`
- แนวคิดสำคัญคือสร้าง `index` ของไฟล์ไว้ เพื่อช่วยบอกว่าข้อมูลที่ต้องการอยู่ตรงไหน
- ถ้า index ไม่ใหญ่มาก อาจเก็บไว้ใน memory เพื่อค้นหาตำแหน่งได้เร็ว
- ถ้า index ใหญ่มาก ก็อาจต้องมี `index ของ index` อีกชั้นหนึ่ง

ภาพจำ:

- เหมือนห้างที่มีรหัสสินค้า `UPC`
- เราไม่ได้เดินหาสินค้าทั้งร้านทีละชิ้น
- แต่ใช้รหัสไปเปิดตารางหรือ index ก่อนว่า item นี้อยู่ตรงไหน

สรุป:

- `Sequential access` เน้นอ่านเรียง
- `Direct access` เน้นกระโดดไปตำแหน่ง
- `Indexed access` เน้นหา "ตำแหน่งของข้อมูล" ผ่านตารางช่วยค้น

เทียบ `Direct access` กับ `Indexed access`:

- `Direct access` ใช้ได้เมื่อเรารู้ตำแหน่งของ block หรือ record ที่ต้องการอยู่แล้ว
- `Indexed access` ใช้เมื่อเรารู้แค่ `key` หรือข้อมูลอ้างอิง เช่นรหัสสินค้า แล้วต้องให้ index ช่วยบอกตำแหน่งจริง
- ดังนั้น `direct access` คือกระโดดไปตำแหน่งทันที
- ส่วน `indexed access` คือเปิดสารบัญก่อน แล้วค่อยกระโดดไปตำแหน่งที่สารบัญบอก

## 5) Directory Structure

directory ใช้เก็บข้อมูลเกี่ยวกับไฟล์และจัดระเบียบ namespace

ภาพง่าย ๆ:

- `directory` เหมือนสารบัญหรือแฟ้มรายชื่อ
- มันไม่ได้เก็บ "เนื้อหาไฟล์" เอง
- แต่มันเก็บว่าไฟล์ชื่ออะไร อยู่ตรงไหน และมี metadata อะไรบ้าง

นึกภาพเหมือนตู้เอกสาร:

- file = เอกสารจริง
- directory = ป้ายชื่อและรายการว่าเอกสารแต่ละใบอยู่ช่องไหน

ดังนั้นเวลาเราพิมพ์ชื่อไฟล์:

- ระบบไม่ได้วิ่งไปหาข้อมูลจริงทั้ง disk แบบสุ่ม
- แต่มันไปดู `directory entry` ก่อนว่าไฟล์นี้อยู่ที่ไหน แล้วค่อยไปอ่านข้อมูลจริง

เทียบกับ `page table`:

- คล้ายกันตรงที่ทั้งคู่เป็นโครงสร้างที่ช่วย "แปลงจากชื่อหรือหมายเลขอ้างอิง ไปยังตำแหน่งจริง"
- `directory` แปลงจาก `file name` ไปยังข้อมูลอ้างอิงของไฟล์
- `page table` แปลงจาก `virtual page number` ไปยัง `physical frame number`
- แต่หน้าที่ต่างกัน เพราะ `directory` อยู่ฝั่ง file system ส่วน `page table` อยู่ฝั่ง memory management
- อีกจุดที่ต่างคือ `directory` เน้นการจัดชื่อไฟล์และ namespace ส่วน `page table` เน้นการแปล address ตอนโปรแกรมรัน

ตัวอย่าง:

- ในโฟลเดอร์ `notes/` อาจมี
  - `os.txt`
  - `db.txt`
  - `network.txt`
- directory ของ `notes/` จะเก็บรายการพวกนี้และข้อมูลอ้างอิงของแต่ละไฟล์
- เมื่อสั่งเปิด `os.txt` ระบบจะค้นใน directory ก่อน แล้วค่อยไปยังตำแหน่งข้อมูลของไฟล์

งานหลักของ directory:

- search
- create
- delete
- list
- rename
- traverse

เหตุผลที่ต้อง organize directory ให้ดี:

- `Efficiency`
เพื่อหาไฟล์ได้เร็ว ไม่ต้องไล่ค้นแบบเสียเวลามาก
- `Naming`
เพื่อให้ตั้งชื่อได้สะดวก เช่นผู้ใช้คนละคนอาจมีไฟล์ชื่อเดียวกันได้ และบางระบบอาจให้ไฟล์เดียวมีหลายชื่ออ้างถึงได้
- `Grouping`
เพื่อจัดไฟล์เป็นกลุ่มตามความหมายหรือคุณสมบัติ เช่นแยกเอกสาร, เกม, รูปภาพ, หรือโปรแกรม Java ไว้คนละโฟลเดอร์

ภาพจำ:

- ถ้าไม่มีการจัด directory ที่ดี ทุกไฟล์จะกองรวมกันเหมือนเอกสารวางมั่วบนโต๊ะ
- พอมีโครงสร้าง directory เราจึงหาเร็วขึ้น, ตั้งชื่อได้เป็นระบบ, และแยกหมวดหมู่ได้ง่ายขึ้น

รูปแบบการจัด directory:

- `Single-level directory`
ง่าย แต่ชื่อชนกันง่าย
- `Two-level directory`
แยกตามผู้ใช้
- `Tree-structured directory`
ยืดหยุ่น ใช้งานจริงบ่อย
- `Acyclic-graph directory`
รองรับการแชร์ไฟล์/โฟลเดอร์

ขยายความแต่ละแบบ:

- `Single-level directory`
ทุกไฟล์ของทุกคนอยู่ใน directory เดียวเหมือนกองเอกสารกองเดียว
ข้อดี:
  - โครงสร้างง่ายมาก
  - implement ง่าย
  ข้อเสีย:
  - ชื่อไฟล์ชนกันง่ายมาก
  - ไม่เหมาะกับหลายผู้ใช้
  - จัดกลุ่มไฟล์ลำบาก
- `Two-level directory`
แต่ละ user มี directory ของตัวเอง โดย `user` ในที่นี้หมายถึงบัญชีผู้ใช้ของระบบ เช่น alice, bob หรือแต่ละ login account
เช่น user A มีของ A, user B มีของ B
ข้อดี:
  - ลดปัญหาชื่อชนกันระหว่างผู้ใช้
  - หาไฟล์ในพื้นที่ของแต่ละ user ง่ายขึ้น
  ข้อเสีย:
  - ยังจัดกลุ่มย่อยภายในของ user ได้ไม่ยืดหยุ่นมาก
  - การแชร์ไฟล์ระหว่าง user ทำได้ไม่สะดวก
- `Tree-structured directory`
มีโฟลเดอร์ซ้อนโฟลเดอร์ได้เหมือนระบบไฟล์ปัจจุบัน
ข้อดี:
  - จัดหมวดหมู่ได้ดีมาก
  - รองรับทั้ง absolute และ relative path
  - เหมาะกับระบบจริงเพราะยืดหยุ่น
  ข้อเสีย:
  - ซับซ้อนกว่าสองแบบแรก
  - ถ้าจัดโครงสร้างไม่ดี path อาจลึกและหาไฟล์ยากขึ้น
- `Acyclic-graph directory`
คล้าย tree แต่อนุญาตให้หลาย directory แชร์ไฟล์หรือ subdirectory เดียวกันได้ โดยไม่ให้เกิด loop
ข้อดี:
  - แชร์ไฟล์หรือโฟลเดอร์ร่วมกันได้
  - ลดการทำสำเนาข้อมูลซ้ำ
 ข้อเสีย:
  - จัดการยากขึ้น เช่นเรื่องลบไฟล์ที่มีหลายชื่ออ้างถึง
  - ต้องระวัง reference counting หรือกลไกดูว่า object ยังถูกใช้อยู่ไหม

เรื่อง `link` ที่เกี่ยวข้อง:

- `Hard link`
คือการมีหลายชื่อชี้ไปยัง file เดียวกันจริง ๆ
- มองง่าย ๆ ว่า directory entry หลายอันอ้างถึง object เดียวกัน
- ถ้าลบชื่อหนึ่งออก ตัวไฟล์ยังอยู่ได้ถ้ายังมีชื่ออื่นชี้อยู่
- ข้อดีคือไม่เกิดไฟล์ขาดเป้าเพราะมันชี้ถึงข้อมูลเดียวกันโดยตรง
- แต่ไม่ดีในกรณีที่ต้องการลบหรือหาเจ้าของไฟล์ให้ชัด เพราะมีหลายชื่ออ้างถึง object เดียวกัน
- และถ้าเอาไปใช้กับ directory จะเสี่ยงทำให้เกิด cycle จนโครงสร้างไม่เป็น `acyclic` อีก จึงมักไม่อนุญาตหรือจำกัดมาก

- `Soft link` หรือ `symbolic link`
คือไฟล์พิเศษที่เก็บ path ไปยัง target อีกที
- มันไม่ได้ชี้ถึงตัว file object ตรง ๆ แต่ชี้ผ่านชื่อหรือ path
- ข้อดีคือยืดหยุ่นกว่า และใช้ข้าม file system ได้ง่าย
- แต่ไม่ดีในกรณีที่ target อาจถูกย้ายหรือลบ เพราะ link จะกลายเป็น `dangling link`
- อีกทั้งมี cost เพิ่มตอนเข้าถึง เพราะต้องตาม path ต่ออีกชั้น

สรุปเชิงใช้งาน:

- ถ้าต้องการแชร์ "ไฟล์เดียวกันจริง ๆ" และอยากให้ลบชื่อหนึ่งแล้วข้อมูลยังอยู่เมื่อยังมีชื่ออื่นอ้างอยู่ แนวคิดจะใกล้ `hard link`
- ถ้าต้องการแค่ทางลัดหรือชื่ออ้างอิงไปยังอีก path หนึ่ง แนวคิดจะใกล้ `soft link`
- แต่ถ้าระบบให้ link อย่างเสรีเกินไป โดยเฉพาะกับ directory จะเสี่ยงต่อ loop, traversal ยาก, และลบยาก จึงต้องควบคุมไม่ให้ graph มี cycle

ภาพจำสั้น:

- `Single-level` = โต๊ะกองเดียว
- `Two-level` = แยกโต๊ะตามคน
- `Tree-structured` = ตู้เอกสารหลายชั้นหลายลิ้นชัก
- `Acyclic-graph` = ตู้ที่บางแฟ้มถูกอ้างถึงได้จากหลายที่

## 6) Path Name

- `Absolute path` เริ่มจาก root
- `Relative path` อิงจาก current directory

ตัวอย่าง:

- `/mail/notes/os.txt` คือ absolute path
- `notes/os.txt` คือ relative path ถ้าอยู่ใน `/mail`

## 7) Mounting

- file system ต้องถูก `mount` ก่อนจึงเข้าถึงได้
- การ mount คือการนำ volume หรือ partition มาผูกเข้ากับ `mount point`
- หลัง mount แล้ว ผู้ใช้จะเข้าถึงมันผ่าน tree เดียวกันของระบบไฟล์

ภาพจำ:

- เหมือนเรามีตู้เอกสารหลักอยู่แล้ว 1 ตู้
- แล้วเอาตู้อีกใบมาต่อเข้าที่ลิ้นชักหนึ่งของตู้หลัก
- จากมุมมองผู้ใช้ มันดูเหมือนเป็นต้นไม้ไฟล์ต้นเดียวกันต่อเนื่องไปเลย

ดังนั้น:

- `mount point` คือโฟลเดอร์ที่ใช้เป็นจุดเสียบ
- file system ใหม่จะไปปรากฏอยู่ใต้จุดนั้น
- ผู้ใช้จึงมองทุกอย่างเป็น tree เดียว แม้จริง ๆ จะมาจากคนละ disk หรือคนละ partition

## 8) Protection

การป้องกันสิทธิ์มีไว้ควบคุมว่าใครทำอะไรกับไฟล์ได้บ้าง

สิทธิ์ที่พบบ่อย:

- read
- write
- execute

ใน Unix/Linux มักอิง 3 กลุ่ม:

- owner
- group
- others

ตัวอย่าง `chmod`:
- คำสั่งอย่าง `chmod 754 file.txt` หมายถึงการตั้งสิทธิ์ให้ไฟล์ `file.txt`
- เลข 3 หลักอ่านจากซ้ายไปขวาเป็น
  - หลักที่ 1 = `owner`
  - หลักที่ 2 = `group`
  - หลักที่ 3 = `others`

ความหมายของเลขแต่ละตัว:
- `4` = `read (r)`
- `2` = `write (w)`
- `1` = `execute (x)`
- ถ้าต้องการหลายสิทธิ์ก็เอามาบวกกัน

ดังนั้น:
- `7 = 4 + 2 + 1 = rwx`
- `6 = 4 + 2 = rw-`
- `5 = 4 + 1 = r-x`
- `4 = 4 = r--`
- `0 = ---`

แปล `chmod 754 file.txt`:
- `7` ของ `owner` = `rwx`
- `5` ของ `group` = `r-x`
- `4` ของ `others` = `r--`

จึงเขียนแบบตัวอักษรได้เป็น:
- `rwxr-xr--`

ภาพจำตำแหน่ง:
- 3 ตัวแรก = สิทธิ์ของ `owner`
- 3 ตัวถัดมา = สิทธิ์ของ `group`
- 3 ตัวสุดท้าย = สิทธิ์ของ `others`

## 9) ใจความสำคัญของบทนี้

- file เป็น abstraction ที่ทำให้จัดเก็บข้อมูลบน disk ได้สะดวก
- directory เป็นตัวจัด namespace และ metadata
- access method มีผลกับรูปแบบการใช้งาน
- mounting ทำให้หลาย file systems เชื่อมเป็นต้นไม้เดียว
- protection สำคัญต่อทั้ง security และการใช้งานหลายผู้ใช้

## Q&A

- Q: `sequential access` คืออะไร?
A: คือการอ่านหรือเขียนข้อมูลตามลำดับจากต้นไปท้าย เหมาะกับไฟล์ที่ใช้งานต่อเนื่อง
- Q: `direct access` คืออะไร?
A: คือการกระโดดไปอ่านหรือเขียนตำแหน่งที่ต้องการได้ทันที โดยไม่ต้องไล่ผ่านข้อมูลก่อนหน้า
- Q: `other access methods` คืออะไร?
A: คือวิธีเข้าถึงข้อมูลที่ใช้ `index` มาช่วยบอกตำแหน่งของ record หรือ block เพื่อค้นหาได้เร็วขึ้น
- Q: `ISAM` คืออะไร?
A: คือวิธีเข้าถึงไฟล์แบบมี index หลายชั้น โดยมี master index ชี้ไปยัง secondary index และไฟล์มักถูกเก็บเรียงตาม key
- Q: `direct access` ต่างกับ `indexed access` ยังไง?
A: `direct access` คือรู้ตำแหน่งแล้วกระโดดไปได้เลย ส่วน `indexed access` คือรู้แค่ key แล้วใช้ index ช่วยหาตำแหน่งก่อน
- Q: `directory` คืออะไร?
A: คือโครงสร้างที่เก็บรายชื่อไฟล์และข้อมูลอ้างอิงของไฟล์ เพื่อให้ระบบค้นหาและจัดการไฟล์ได้
- Q: `directory` concept เหมือน `page table` ไหม?
A: คล้ายกันตรงที่เป็นตารางอ้างอิงไปยังตำแหน่งจริง แต่ `directory` ใช้กับไฟล์และชื่อไฟล์ ส่วน `page table` ใช้กับการแปล virtual address ไป physical memory
- Q: ทำไมต้อง organize directory?
A: เพื่อให้หาไฟล์ได้เร็ว (`efficiency`), ตั้งชื่อได้สะดวก (`naming`), และจัดไฟล์เป็นหมวดหมู่ตามความหมาย (`grouping`)
- Q: `single-level directory` ข้อดีข้อเสียคืออะไร?
A: ข้อดีคือเรียบง่าย แต่ข้อเสียคือชื่อชนกันง่ายและจัดกลุ่มไฟล์ได้ไม่ดี
- Q: `two-level directory` ข้อดีข้อเสียคืออะไร?
A: ข้อดีคือแยกไฟล์ตามผู้ใช้และลดชื่อชนกัน แต่ข้อเสียคือแชร์ไฟล์และจัดกลุ่มย่อยยังไม่ยืดหยุ่นมาก
- Q: `tree-structured directory` ข้อดีข้อเสียคืออะไร?
A: ข้อดีคือจัดหมวดหมู่ได้ดีและยืดหยุ่นมาก ส่วนข้อเสียคือโครงสร้างซับซ้อนขึ้น
- Q: `acyclic-graph directory` ข้อดีข้อเสียคืออะไร?
A: ข้อดีคือแชร์ไฟล์หรือโฟลเดอร์ร่วมกันได้ ส่วนข้อเสียคือการจัดการ reference และการลบซับซ้อนขึ้น
- Q: `hard link` กับ `soft link` ต่างกันยังไง?
A: `hard link` คือหลายชื่ออ้างถึง file เดียวกันจริง ๆ ส่วน `soft link` คือไฟล์พิเศษที่เก็บ path ไปยัง target อีกที ดังนั้นถ้า target ถูกลบ `soft link` จะขาดเป้าได้ แต่ `hard link` ที่เหลือยังใช้งานไฟล์เดิมได้
- Q: `mounting` คืออะไร?
A: คือการเอา file system อีกก้อนมาผูกเข้ากับ `mount point` เพื่อให้มันปรากฏเป็นส่วนหนึ่งของ tree เดียวกันของระบบ
- Q: `chmod 754` แปลว่าอะไร?
A: หมายถึง `owner = rwx`, `group = r-x`, `others = r--` โดยเลขแต่ละหลักแทนสิทธิ์ของแต่ละกลุ่มผู้ใช้
